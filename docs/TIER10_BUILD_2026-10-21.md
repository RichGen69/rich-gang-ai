## Failures found & fixed

1. **CharacterDef parser would crash on the expansion entries.**
   `VoiceCasting.fromJson` and the baseline read used strict casts
   (`as String`, `as Map`), so any entry without voice/baseline keys
   threw — which would have emptied the whole registry in-app.
   Fixed at the parser level: voice/baseline/interests/roles/
   talkativeness now default safely; missing voice yields the
   `VoiceCasting.uncast` sentinel (empty ids, `isUncast`), and the
   entry's `status` field — not parser defaults — is the source of
   truth for "unconfigured". Covered by fixture + real-asset tests.
2. **My own registry tests failed: Kelly's id.** The tests assumed
   `cougar_kelly`; the shipped asset's Kelly id is `crazy_kelly`
   (see Registry-only section for the concurrent swap). Fixed the
   tests to the real id and re-ran green. Root cause was my
   assumption from earlier notes, not the data.
3. **HTML template misrepresented portrait-less agents.** The Stage
   panel's note said "this is their Hollywood portrait" even when no
   portrait existed (image hidden). Fixed to a conditional note that
   states registry-only status and that no image is shown. The cast
   poster panel now captions that the poster shows only the original
   nine, and the header count now reads "22 AGENTS IN THE REGISTRY —
   9 FULLY CONFIGURED" instead of "22 AGENTS IN THE ROOM". The
   builder's uncast label was aligned to "Uncast — not configured".
   Then regenerated + verified (above).
4. **HUD orphan risk.** The first implementation route (standalone
   widget only) would have left the controller uninstantiated —
   an island. Fixed by mounting `Tier10Hud` in The Room and giving
   every `InferenceRouter` a controller by default (injectable),
   with the registry count pushed from The Room's real load.
5. **Invented-value traps in my own first pass, removed before
   shipping:** expansion entries briefly carried explicit
   `talkativeness/volatility: 0.5` and the original nine a `status`
   field beyond the specified zodiac addition. Both were stripped —
   expansion entries omit those keys (parser defaults + status flag
   carry the truth), and the original nine gained only `zodiac`.
