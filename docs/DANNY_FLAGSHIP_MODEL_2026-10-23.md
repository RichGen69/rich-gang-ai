**Flagship chain of thought** (`lib/core/danny_chain.dart`) —
named, real stages, run in the one-to-one chat for Danny on
EVERY reply (his DOUBLE-CHECK gift makes critique/revise
mandatory; the Deep toggle neither enables nor disables his
chain). Other characters keep the shared think-step/DeepReasoner
paths untouched.

1. **perceive** — TimeContext from the real device clock
   (clock/date/weekday/daypart, session elapsed, gap since his
   last interaction), his live self-state report, his ledger
   summary, lexical appraisal of the stimulus, and — when the
   message turns on current facts — the existing WebSearch path
   (DDG Instant Answer + Wikipedia; empties/failures reported,
   never filled in).
2. **appraise** — the shared Thinker think-step (structured
   CoT JSON), steered by his real affect.
3. **discern** — the discernment pass (below) over the stimulus
   and the think-step's memory claim.
4. **draft** — full inference pass.
5. **critique** — inference pass attacking the draft, with the
   discernment flags in front of it. Never skipped.
6. **revise** — inference pass; the revision is the answer.
7. **respond** — the revised text ships; the draft never does.
8. **reflect** — self-model writes from the real exchange
   (interaction, topics, commitments), a chain reflection note,
   and ledger entries for whatever the stimulus appraised as.

The stage trace is data — the chat UI shows it under his
replies ("Danny's chain — perceive to reflect, checked twice")
next to the critique expander the app already had.

**Discernment / SECOND SIGHT** (`lib/core/danny_discernment.dart`).
Deterministic lexical cross-check of claims against the daemon's
recorded witness facts (rga_witnesses / rga_witness_facts — the
scene data Richard supplies; the FFI view never serializes lie
text, so checks run against on-record truth). Verdicts:
CONSISTENT-WITH-FACTS / INCONSISTENT-WITH-FACTS (negation
mismatch or disagreeing numbers against a content-matching
fact) / NO-FACT-COVERAGE. **This is consistency-checking against
a recorded table, NOT a lie detector**, and it is named that way
in code, in the prompts it feeds, and here. The shipped config
supplies no scene facts, so in the shipped configuration the
pass honestly reports NO FACTS AVAILABLE and verifies nothing —
it starts checking the day Richard supplies scene data.

**Self-upgrade with guardrails** (`lib/core/danny_upgrades.dart`).
Bounded parameter self-tuning on top of the self-model:
- ALLOWLIST ONLY: baseline_pleasure/arousal/dominance (each
  ±0.15 of authored), talkativeness/volatility (±0.10 bands),
  and a self_note (≤280 chars). Everything else — moral_core,
  guardrails, core, voice, portrait, status, identity, other
  characters — is rejected with an explicit
  DannyUpgradeException, by construction (no code path writes
  them). Out-of-band values are REJECTED, not silently clamped.
- DRIVER: DeepDream's reflection for Danny calls
  `tuneFromReflection` — baselines nudged 10% toward his current
  affect, inside the bands, only when the movement is real
  (≥0.005); otherwise nothing is written and no upgrade claimed.
- ACCOUNTABILITY (the responsibility machinery): every accepted
  change is a versioned snapshot (state before/after, reason,
  timestamp) appended to his accountability log; rejections and
  kill-switch flips are logged too. Rollback restores a snapshot
  by APPENDING a rollback entry — history is never rewritten,
  and the class exposes no edit/delete operation at all
  (test-asserted). Richard can review and roll back; Danny
  cannot clean his own record.
- KILL SWITCH: persisted `enabled` flag, default ON — on
  because every guardrail test passes (26 Danny tests, below);
  while off, every attempt fails explicitly and is logged.
- This is parameter-level self-tuning from his reflection/dream
  cycle. It is NOT model retraining and NOT code
  self-modification, and nothing here calls it that.
