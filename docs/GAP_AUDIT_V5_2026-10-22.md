## Honest build sequence if Richard wants v5 pursued
1. Unblock APK (other_tcp → Ask) → build → device-verify current verified build on A16. Do not layer v5 on an unverified base.
2. Spike, one at a time, with a compile+test proof on aarch64-linux-android: tokio, rusqlite (bundled), petgraph (pure Rust, likely easiest), memmap2.
3. Hard spikes, separate decisions: llama-cpp-rs + Vulkan on Adreno, candle, LanceDB — each is a large dependency, likely size/startup cost on mobile, and may not cross-compile cleanly. No promise before a spike passes.
4. Mesh: design first (discovery, trust/pairing, encryption) — raw multicast with no auth would be a security regression, not a feature.
5. Riverpod migration, tactical map, memory inspector, telemetry views: UI work, only after 1–2, and telemetry must show measured values only (latency stays null until measured).
6. Compliance layer: define what it actually enforces in code/tests before naming it TRAIGA or anything else.

Each step: verify crate/API from primary docs before coding (Richard's rule), tests green, docs updated, publish gate re-checked. Nothing publishes before the gate passes and Richard gives final approval on the exact build/copy.
