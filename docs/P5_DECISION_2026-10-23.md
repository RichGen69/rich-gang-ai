## 1. LanceDB — REJECTED

**Decision: do not integrate LanceDB. Semantic/vector memory
stays on the already-integrated rusqlite store plus lexical
recall until a lighter candidate earns its own spike.**

Evidence (`docs/SPIKE_V5_006_LANCEDB.md`, LanceDB 0.40.0):

- **Default features do not compile** — an upstream bug:
  `error.rs` gates the `Http` error variant behind the `remote`
  feature while `job.rs` uses it ungated (E0599). The crate as
  published cannot be consumed the documented way.
- The `remote` workaround compiles and passes host functional
  tests (3/3), but drags a server stack (axum / tonic /
  arrow-flight / oauth2) into a local-only store — the opposite
  of this app's on-device posture.
- Cost: a 521-crate dependency tree, ~13 GB of debug target, a
  2.0 GB host test binary, and a full Android build that did not
  finish inside a 900-second box (~361/~521 rlibs when stopped) —
  against rusqlite, which is already integrated, WAL-verified,
  and serving the shipped config as of this sweep's P6 item.
- The spike's "embeddings" were fixture vectors by design; no
  semantic capability was demonstrated that rusqlite + lexical
  recall lacks a plan for.

Revisit only if: a future LanceDB release fixes the
default-features build, the dependency tree shrinks materially,
and a named workload needs vector search the rusqlite store
cannot serve. Any revisit starts as a fresh spike, not an
integration.

## 2. llama-cpp-2 — INTEGRATION DESIGN ONLY, gated on Richard's model pick

Spike verdict (`docs/SPIKE_V5_005_LLAMA_CPP.md`): **PASS at spike
level** — llama-cpp-2 0.1.160 compiles on host (backend-init test
passed) and for Android aarch64 (objects verified ARM aarch64).
Two hard limits ride with that verdict:

- **Inference itself is untested.** No model exists in this
  environment and none was downloaded; no token has ever been
  generated by this stack here.
- **Vulkan is UNPROVEN** — the probe failed at CMake configure
  ("Could NOT find Vulkan … glslc") because this VM lacks the
  Vulkan SDK/headers. That is an environment finding, not a crate
  failure; GPU offload on the A16 is an open question for the
  device phase, and the design below assumes CPU inference.

### 2.2 Size budget (proposal, for Richard's approval with the pick)

- Model file: **≤ 1.2 GB** (Q4_K_M, 1B–1.5B class). A 3B model
  doubles the footprint for capability this app does not need
  from its local path — the local model is the offline/fallback
  brain, not the flagship brain.
- Library: the spike's Android `libllama.a` was **74 MB in a
  debug build**. That number is a warning, not a budget figure:
  the integration spike must measure the release `.so` that
  actually ships, and the total added install footprint
  (library + model) must be reported before any marketing claim.
- Runtime RAM: weights (~1 GB) + KV cache (context capped at
  4096 tokens in the design) + runtime overhead must be measured
  on the A16 itself; an out-of-memory failure mode must be an
  explicit error state, never a crash-or-fake.

### 2.3 Integration outline (design only — no code in this sweep)

1. **Rust core:** a `local_llm` module behind the existing
   `edge_inference` surface, wrapping llama-cpp-2. Today
   `edge_inference` returns explicit errors; it keeps doing so
   until this integration is built and device-verified.
2. **Config:** daemon config gains `model_path` (absolute path
   under the app files/support directory, delivered by the same
   runtime-config builder as P6's `store_path`). No config, or a
   missing file, yields the explicit error states
   `no_model_configured` / `model_file_missing` /
   `model_load_failed` — the UI renders those as "no local model
   installed", never as a silent cloud substitution.
3. **FFI:** additive `rga_edge_*` exports (load state, generate,
   unload) with ABI discipline per the release gate: rebuild,
   restage, `release_gate.sh --suites` PASS before the item
   counts as done.
4. **Model delivery:** the model is NOT bundled blind. Delivery
   is a user-initiated download into the app files directory
   with the licence shown and acceptance recorded, or a manual
   file placement the app verifies (size + SHA-256 against the
   pinned values from the pick).
